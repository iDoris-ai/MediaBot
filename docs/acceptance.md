## 二、社区运营（组织）

### Twitter

1. **每天自动发帖**
2. **搜索相关话题 → 到话题下回复**
3. **回复必须有理有据**——基于我们自己的背景/产品/信息，结合该 topic 的关键词。
   **不是瞎写、不是套话。** 这条是硬标准：宁可不回，不能水。

当前状态：⚠️ 发帖 + 回复自己帖子的评论已通；**主动搜话题去回复**（outbound）已实现但默认关闭，且质量门槛靠 prompt 约束

### Telegram

1. **群内定时发信息**
2. **自动回复群里的一些信息**

当前状态：⬜ 未做。本地已有可借鉴实现：`~/Dev/tools/telethon/CBots`（telethon + 反广告 + 命令处理 + 网页发消息）

### Reddit

原始需求：运行几个号，各自不同人设，逛/搜索/查看，偶尔点赞、回复；每个人设关注特定话题，只发短反馈不发长文；产品有变化时才发相关内容；"以正常用户心态发，不滥用"；目的是节约人力。

当前状态：⬜ 未做。**且这条需求需要先讨论边界，见下节。**

## 三、一处需要先对齐的边界：Reddit 多人设

**必须先说清楚，因为这关系到要不要建这套能力。**

「运行多个账号、各自扮演不同的人、给自己产品点赞和背书」，在 Reddit 的规则里叫 **vote manipulation + astroturfing**，是明令禁止的，不是灰区：

- 多账号协同投票 → 触发反作弊，**关联账号一起封**，包括你的主号
- 伪装成独立用户推荐自己产品 → Reddit 社区对这个的反应比广告激烈得多
- 一旦被扒出来（Reddit 用户很擅长扒），**对品牌的伤害远大于省下的人力**

你的出发点是「节约人力」不是「骗人」，我理解。但**机制本身构成欺骗**——读者以为看到的是几个独立用户的自发意见，实际是同一方的多个马甲。这一点和出发点无关。

**能达到同样目的、且不踩线的做法**：

| | 不建议 | 建议 |
|---|---|---|
| 账号 | 多个虚构人设 | **一个公开属于你/公司的账号** |
| 自动化的部分 | 伪装成人、自动点赞背书 | **监控相关讨论、起草回复给你过目** |
| 身份 | 隐藏关联 | 简介里写明身份，回复时该披露就披露 |
| 省下的人力 | — | **90% 都省了**——耗时的是找帖子和写初稿，不是点发送 |

如果团队里本来就有几个真人各自有 Reddit 账号，**每个人用 MediaBot 起草自己的回复**——那完全没问题，人设是真的。我可以做这个。

我不会做的是：**批量生成虚构人设 + 自动点赞/互推的基础设施**。这不是能力不够，是它会把你的账号和品牌一起搭进去。

**这条需要你确认走哪个方向，我再动手。**

## 四、验收时怎么判断「好用」

1. **一条内容，多平台形态正确** —— 不是复制粘贴，小红书像小红书，公众号像公众号
2. **回复质量能看** —— 随机抽 10 条自动起草的回复，能直接发出去的 ≥ 7 条
3. **我每天花的时间 ≤ 30 分钟**，且全花在审阅上，不在操作上
4. **不出事故** —— 没有误发、没有重复发、没有发出我没批准的东西
5. **平台账号安全** —— 不因为自动化被限流或封号
